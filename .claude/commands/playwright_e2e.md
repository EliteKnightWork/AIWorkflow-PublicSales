# Playwright MCP を利用して E2E テストを実施

## ログイン情報

[playwright_e2e/.info.json](playwright_e2e/.info.json) に以下のログイン情報を設定する必要がある

```json
{
  "LABID_LOGIN_EMAIL": "email",
  "LABID_LOGIN_PASSWORD": "password"
}
```

## 出力先

- 出力先ディレクトリ: [playwright_e2e/output](playwright_e2e/output)
- テスト結果ファイル: [playwright_e2e/output/result.md](playwright_e2e/output/result.md)

## オプション

`$ARGMENTS`: $ARGMENTS で以下のオプションを指定可能

- `--capture`: スクリーンショットオプション
  - 各テスト項目の実施後にスクリーンショットを取得
  - ファイル名: {テスト項目番号(001, 002, ...)}-{テスト項目名(top, login, ...)}.png

## 使用コマンド

- `docker compose ps -a` - Docker コンテナの状態を確認
- `docker compose up -d` - Docker コンテナをバックグラウンドで起動
- `docker compose stop` - Docker コンテナを停止
- `lsof -i :8080` - クライアントが起動しているか確認
- `cd new_client && yarn dev > /dev/null 2>&1 &` - クライアントをバックグラウンドで起動
- `lsof -ti :8080 | xargs kill` - クライアントを停止

## ワークフロー

1. [ログイン情報](#ログイン情報)が設定されているか確認し、設定されていない場合はユーザーに具体的な設定方法を通知し、テストを中止する
2. `$ARGMENTS` の値を確認し、[オプション](#オプション)が指定されているか確認する
3. [出力先](#出力先)ディレクトリをクリーンアップし、必要なディレクトリを作成する
4. Docker コンテナが起動しているか確認し、起動していない場合は起動する
5. クライアントが起動しているか確認し、起動していない場合はバックグラウンドで起動する
6. [テスト項目](#テスト項目)に従い、 Playwright MCP を利用して E2E テストを実施する
7. テスト終了後に Playwright を停止する
8. 「5. クライアントが起動しているか確認」の手順でクライアントを起動した場合は、テスト終了後にクライアントを停止する
9. 「4. Docker コンテナが起動しているか確認」の手順で Docker コンテナを起動した場合は、テスト終了後に Docker コンテナを停止する
10. テスト結果を確認し、[テスト結果ファイル](playwright_e2e/output/result.md)のマークダウンを作成する

## テスト項目

1. トップページ(`/`)が表示されること
2. ログインボタンをクリックするとログインページが表示されること
3. [ログイン情報](#ログイン情報)を入力してログインできること
4. サイドバーのマイページをクリックするとマイページ(`/mypage`)が表示されること
5. サイドバーの案件管理をクリックすると案件管理(`/management`)が表示されること
6. サイドバーの案件をクリックすると案件一覧(`/projects`)が表示されること
7. サイドバーの落札企業をクリックすると落札企業(`/bidCompanies`)が表示されること
8. サイドバーの発注企業をクリックすると発注企業(`/organizations`)が表示されること
9. サイドバーの設定をクリックすると設定のポップアップが表示されること
10. 設定のポップアップでサイドバーの会員情報をクリックすると会員情報が表示されること
11. 設定のポップアップでサイドバーのイチオシ案件をクリックするとイチオシ案件が表示されること
12. 設定のポップアップでサイドバーの配信をクリックすると配信設定が表示されること
13. 設定のポップアップでサイドバーのメンバーをクリックするとメンバー一覧が表示されること
